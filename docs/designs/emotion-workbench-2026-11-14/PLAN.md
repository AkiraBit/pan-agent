# PanWatch 情绪策略台完整设计方案

版本：设计稿 v1 · 2026年11月14日 · 设计范围：产品、Agent、数据契约、交互原型与实施路线。

## 1. 产品决策

将现有「短线指南」演进为「情绪策略台」，沿用 `/short-term` 入口。它持续维护市场判断、周期关系、观察预案、证据和复盘结果。用户打开页面就能知道：现在如何判断、相比上次改变了什么、接下来验证什么、哪些结论暂时不能信。

Agent 拥有分析内容与页面编排权：可以发现新周期、修改角色、提出竞争解释、生成观察规则、选择图表和模块。程序拥有事实计算、规则执行、校验、时间边界、权限和渲染权。通过受约束的结构化协议连接两者。

本次交付是完整方案与可交互原型，包含七个视图、四种数据情景、证据弹窗、上下文补充、个股切换、明暗主题、移动端布局和结构化快照导出。真实行情接入、模型运行、自动监测及通知属于后续实施范围。原型未修改生产页面、数据库或真实监测配置。

## 2. 把本轮讨论变成产品需求

| 本轮实际问题 | 页面应承担的工作 | 可验证结果 |
| --- | --- | --- |
| 看跌停就直接判断整个周期结束 | 同时读取监管、异动窗口、交易时段与跨周期状态 | 每条阶段判断附支持、反证和未决约束 |
| 用户补充新华监管、九阳窗口、周末因素后才改判 | 持续核验事件、计算窗口、检索已记录上下文 | 关键约束不会在下一次分析中丢失 |
| 把九阳上涨等同于全周期恢复 | 独立评估核心主动性、分支扩散、接力持续性 | 单股独强与周期修复呈现不同情景 |
| 把所有上涨归到同一周期 | 保留传媒独立走强、新周期形成等竞争解释 | 周期可以分裂、重叠、衰减和归档 |
| 周一预案依赖用户记住股票、时点、条件 | 自动记录与检查分时段预案 | 每个检查点有状态、依据、时间和下一步 |
| 闽发修复与反包容易混淆 | 确定性计算涨跌停价，区分结构恢复层级 | 不产生超过当日涨停价的当日触发条件 |
| 后来观点覆盖此前错误判断 | 不可变版本、修订原因、当时可见证据 | 可以回放“当时知道什么” |
| 没数据时仍然给方向 | 能力探测、时效门控和未知状态 | 停止依赖缺失数据的判断，保留最后有效快照 |

关键事实：当前 `analysis.py` 明确输出 `auction.available = false`，原因为 `no_verified_auction_feed`。五秒读取已保存快照不等于五秒采集行情，也不等于已有连续自动盯盘。现有14天清理不能承担跨月周期记忆；需在清理前保存被分析引用的必要证据与摘要，形成独立保留策略。

## 4. 信息架构与页面

全局导航沿用产品外壳。情绪策略台内部提供七个稳定入口，Agent 只改变内容区，不随意改变导航位置。

| 页面 | 建议路由 | 用户主要问题 | 核心模块 |
| --- | --- | --- | --- |
| 总览 | `/short-term` | 现在怎么看，下一步看什么 | 当前判断、三项关键约束、变化摘要、接力链、观察池 |
| 周期地图 | `/short-term/cycles/:id` | 哪些票属于同一段行情，关系成立吗 | 多周期切换、角色节点、类型化连线、分支比较、时间回放 |
| 看盘预案 | `/short-term/playbooks/:id` | 竞价、开盘与午后分别验证什么 | 竞争情景、观察时段、条件状态、失效路径、冻结版本 |
| 核心标的 | `/short-term/stocks/:symbol` | 这只股票承担什么角色 | 行情与价格参照、结构、约束、分支对照、个股预案 |
| 证据与约束 | `/short-term/evidence` | 判断用了什么，哪些还不确定 | 原文出处、时点、核验状态、冲突、监管与窗口日历 |
| 复盘档案 | `/short-term/reviews/:date` | 原计划发生了什么，为什么改判 | 不可变预案、条件结果、版本差异、遗漏归因、案例记忆 |
| Agent 工作记录 | `/short-term/agent` | 是否在工作，缺什么数据 | 工作状态、运行记录、能力健康、费用预算、输出发布记录 |

### 总览的固定阅读顺序

第一屏优先回答当前判断、关键约束和下一检查点。核心观察池按角色组织，点击直接进入详情。原始市场广度、涨跌停数量、梯队等背景资料可以下钻，避免首屏充满没有解释的数字。

用户可固定重要模块。盘中同一阶段保持布局稳定，重要变化在原位置标注，不因每次模型输出重排整个页面。新模块在侧栏或指定增量区出现；切换阶段或用户确认更新后再调整整体顺序。

### 周期地图

节点包括股票、题材、事件和周期。股票可有多个角色，并附有效区间。连线区分 `business_relation`、`name_association`、`observed_co_move`、`relay_hypothesis`、`contradiction`。业务事实用实线，待验证关系用虚线，不能把所有箭头都画成确定资金传导。

阶段允许启动、扩散、分歧、修复、退潮、归档及不确定；同一周期不同分支可以处于不同阶段。不能强制全市场只有一个阶段。显示每次角色变化的依据和版本。

### 预案与个股

预案同时保存主情景、竞争解释与失效路径。每个情景有必要条件、支持证据、反证、观察窗口、更新策略。个股页继承周期上下文，同时保留独立约束；九阳窗口变化不会自动解除闽发约束。

行情价格、状态与阶段标签不能仅靠颜色表达。每个价格显示数据时间。部分 K 线、历史数据和模拟数据分别标注。图表不得为了好看补造缺失行情。

### 证据、复盘与运行

用户纠正以“用户补充，待核验”保存，提供原文时生成核验任务。用户可以决定关注范围与提醒偏好，但不能通过一句话把传闻升级为事实。

复盘区只显示已到观察终点的结果；未结束样本标为待观察，缺数据标为不可评估。运行区保存简洁的执行摘要、工具结果、错误、模型与规则版本，不要求暴露模型内部思维链。

## 5. Agent 的能力模型

以一个主 Agent 加明确的分析步骤实现第一版，无须一开始部署多个自治 Agent。每一步可以独立测试，后续有评估收益再拆分。

1. **市场扫描**：读取广度、涨跌停、连板同组、成交、题材和历史快照，提出候选周期。
2. **事件与约束核验**：检查监管、公告、减持停复牌、异动窗口和交易日历；发现冲突则保留多源差异。
3. **周期与角色分析**：解释赚钱与亏钱效应，区分核心、补涨、穿越候选、属性桥梁和新方向；附反证。
4. **竞争情景检查**：主动检验独强、板块普涨、消息驱动、旧周期修复与新周期替代等解释。
5. **预案编译**：将有意义的判断转为程序可执行规则，无法量化的部分明确标为待 Agent 解释。
6. **页面编排**：根据阶段、用户关注与数据能力，选择注册模块及顺序。
7. **增量修订与复盘**：由新证据触发，记录改变原因，归档可复用经验。

“高手”的产品定义是持续发现、检验并修订假设，控制证据边界。不能以总能给出确定结论或保证收益作为验收标准。

### 战法知识如何落地

Agent 按“市场环境 → 周期与题材 → 股票角色 → 观察预案”逐层分析。市场层判断短线赚钱效应和亏钱效应；周期层判断梯队、分支与竞争方向；个股层判断主动性、辨识度、换手、承接和约束。任何个股结论都能回到这三层证据。

战法以版本化的 `StrategyDefinition` 保存，包含适用环境、必要数据、支持特征、反证、观察期限、退出条件和案例引用。它是候选解释模板，不是“出现某形态必涨”的规则。

| 战法模板 | 重点验证 | 常见反证 |
| --- | --- | --- |
| 龙头与梯队接力 | 核心主动性、同组晋级、跟随广度、下一交易日溢价 | 核心独强、跟随者亏钱、晋级样本被偷换 |
| 分歧转修复 | 冻结弱势组的承接改善、修复持续时间、相对市场表现 | 只剩脉冲反弹、午后回吐、负反馈扩大 |
| 补涨扩散 | 与原周期的证据关系、启动先后、新梯队形成 | 仅名字相似、旧核心已失效、补涨无人接力 |
| 趋势穿越 | 多次分歧中的相对强度、量价结构和独立催化 | 把短暂抗跌直接认作穿越成功 |
| 新旧方向切换 | 新方向内部广度与持续性、旧周期负反馈 | 单股消息行情、市场普涨被误认成新周期 |
| 退潮中的反抽 | 自身结构修复与整个周期恢复分开评估 | 一次涨停就宣布反包完成或新周期启动 |

确定性特征包括涨跌停分布、炸板、封板时长、冻结梯队晋级、前日强势组次日表现、成交集中度、分支相对收益及回撤。每个特征携带定义版本、样本范围、单位、采样窗口与覆盖率；缺失封板时序时不生成封板质量指标。模型可以请求研究新特征，但不能在正式预案中暗自新增算法或更改口径。

经验进入案例库前必须有完整的事前假设、观察过程与事后结果。相似案例用于提出反证和待检验路径，不直接继承历史胜率。策略模板修订先经过历史走步回放和旁路运行，固定版本进入正式监测，防止单次复盘就自动改变所有规则。

### 工具边界

允许读取 `get_market_snapshot`、`get_security_history`、`get_theme_cohort`、`get_verified_events`、`calculate_abnormal_window`、`get_cycle_memory`、`evaluate_conditions` 等领域工具；允许通过受控发布工具保存分析结果。工具参数接受规范化证券ID，不能仅用中文简称检索后直接交易。

模型不执行任意 SQL、代码、网页脚本或下单。行情计算与监管窗口不交给模型心算。用户上传图片和外部文章属于证据材料，不拥有修改工具权限或系统指令的能力。

## 6. 自动工作的节奏

| 时段或触发 | 程序工作 | Agent 工作 | 用户看到 |
| --- | --- | --- | --- |
| 周末 / 盘前 | 拉取允许来源的新事件、核验日历 | 整理周期、约束和竞争情景 | 次日预案与未决问题 |
| 09:15—09:25 | 在竞价源可用时采样并记录质量 | 解释最终竞价组合，避免早期挂单过度推断 | 竞价检查结果或能力缺失 |
| 09:30—10:30 | 按行情许可频率检查已编译条件 | 核心响应或分支变化时增量分析 | 接力链状态与关键变化 |
| 午间 / 午后 | 时段切换、事件归档、条件检查 | 重要新消息或明显失效时改判 | 原情景、修订原因和下一步 |
| 收盘后 | 冻结快照、计算当日结果 | 复盘与次日预案 | 结果账本和新的预案草稿 |
| 下一交易日 | 检查已冻结观察池的后续表现 | 评估接力持续性 | 次日溢价，不追溯换样本 |

不按每个 tick 调用大模型。高频采样与规则计算使用普通程序；模型由节点、重要条件变化、关键事件或手动请求触发。设置单周期串行发布、请求合并、去重、冷却与日预算。默认盘中预算应由实际压测与模型成本确定，不承诺未经测量的实时频率。

开始监测是一项用户可控制的产品配置。停止后停止后续任务，不删除历史。仅重大变更通知，通道继承用户已配置的权限与偏好。原型里的开关只切换本地演示状态。

## 7. 结构化数据契约

分开四层数据，避免让页面布局成为金融事实的唯一载体。

```text
源数据与不可变快照
  → FactBundle：事实、事件、质量、时间与口径
  → AnalysisDocument：周期、角色、判断、竞争情景、反证
  → MonitoringPlan：观察范围、可执行条件、时点、失效规则
  → ViewSpec：页面、模块引用、优先级与允许的动作
```

生产包 `WorkspacePublication` 至少包含：

| 对象 | 必需字段 |
| --- | --- |
| 发布头 | `schema_version`、`publication_id`、`revision`、`parent_revision`、`run_id`、`workspace_id`、`generated_at`、`knowledge_cutoff`、`target_trade_date`、`timezone` |
| 数据快照 | `snapshot_id`、`market_as_of`、`source_id`、`source_scope`、`universe_id`、`coverage`、`freshness`、`capabilities` |
| 证据 | `id`、`kind`、`source_url`、`published_at`、`observed_at`、`valid_from/to`、`verification_status`、`content_hash`、`source_ref` |
| 判断 | `id`、`statement`、`status`、`support_evidence_ids`、`counter_evidence_ids`、`assumptions`、`invalidators` |
| 周期与角色 | `cycle_id`、`stage`、`stage_scope`、`members`、`role_validity`、`edges`、`alternative_cycle_ids` |
| 情景 | `id`、`required_conditions`、`contradicting_conditions`、`state`、`reason`、`review_at` |
| 条件 | `id`、`expression`、`data_requirements`、`window`、`dwell_ms`、`state`、`observed_value`、`triggered_at`、`invalidated_at` |
| 页面模块 | `id`、`kind`、`entity_refs`、`priority`、`slot`、`actions`、`empty_policy` |
| 修订 | `changed_claim_ids`、`new_evidence_ids`、`reason`、`superseded_refs` |

每个数值都带单位与定义；百分比使用统一数值口径，货币明确人民币元，成交量明确股或手。股票通过 `market + code + exchange` 规范化。跨日回放同时约束事件发生时间、公开时间与系统获知时间，防止未来信息进入历史判断。

### 可执行条件示例

以下阈值仅展示协议表达能力，不是当前市场的已验证策略参数。

```json
{
  "id": "jy-hold-example",
  "label": "九阳站稳观察参照",
  "evaluation_mode": "deterministic",
  "window": {
    "trade_date": "2026-11-16",
    "start": "09:30:00",
    "end": "10:30:00",
    "timezone": "Asia/Shanghai"
  },
  "expression": {
    "op": "all",
    "args": [
      {
        "op": "gte",
        "left": {"metric": "last_price", "security_id": "CN:SZ:002242"},
        "right": {"value": 27.04, "unit": "CNY", "source_ref": "prior-week-high"}
      },
      {
        "op": "gte",
        "left": {"metric": "relative_return_to_benchmark", "security_id": "CN:SZ:002242"},
        "right": {"value": 0, "unit": "percentage_point"}
      }
    ]
  },
  "dwell_ms": 180000,
  "data_requirements": {
    "max_age_ms": 30000,
    "max_observation_gap_ms": 10000,
    "required_capabilities": ["timestamped_quote", "benchmark_quote"]
  },
  "on_missing": "unknown",
  "state": "waiting",
  "observed_value": null
}
```

运行程序只解释白名单 AST 算子，不执行字符串表达式。采样间断不能连续累计满足时长；需要明确跨午休是否延续。动态条件如“首次回落有承接”必须先定义峰值识别、回落阈值、时间窗口与量价条件，再编译成程序规则；未定义时标为 `agent_review`，不能伪装为已经自动判定。

条件状态为 `waiting / met / not_met / unknown / invalidated / expired`。阶段判断采用 `supported / contested / insufficient / superseded` 等证据状态。不要把四项满足三项显示成75%上涨概率。若需要概率，必须另建带样本、校准和误差说明的模型。

### 原型中的契约

`demo-data.js` 产生四个示例快照，`app.js` 通过 `pages[page][].kind` 从渲染注册表选择组件。分析标题、观察池、周期节点与关系、分支判断、情景、时段预案、条件、约束、经验与修订均来自结构化数据。页面壳、固定栏目标签、交互组件和状态解释由程序提供。

`prototype.schema.json` 验证原型快照的结构；`example-output.json` 是可导出的完整周末示例。原型语义条件不冒充已编译规则，生产契约需要在实施第一阶段细化为 Pydantic DTO 与前端生成类型。

## 8. 自适应页面的范围

第一批注册模块包括：当前判断、约束提示、市场指标、周期图、角色观察池、情景对照、分时段预案、条件清单、个股结构、价格参照、来源证据、变化摘要、复盘结果、运行状态、数据缺口。

Agent 可选择模块、绑定数据、确定展示优先级、建议布局槽位和生成解释文本。程序限制模块数量、最大深度、字符串长度、链接协议、图表点数及动作类型；禁止任意 HTML、JavaScript、CSS、iframe 和模型生成的可执行代码。

缺失模块显示可理解的回退卡，不导致全页崩溃。原始结构仍可导出。带关键数据缺口的模块必须保留缺口提示，不能通过不展示模块掩盖它。页面顶部的时间、模拟状态、运行状态与关键约束不能由 Agent 删除。

不同阶段采用不同内容组合：

- 周末预案突出约束、情景与下个检查点。
- 竞价阶段突出匹配结果和数据能力。
- 盘中阶段突出已发生变化、核心响应和失效提示。
- 退潮风险增加时提高负反馈与反证的展示优先级。
- 数据失效时展示最后有效快照、暂停条件和恢复路径。
- 收盘后突出预案结果和修订原因。

## 9. 发布、记忆和恢复

### 发布流程

Agent 输出先进入草稿。执行 JSON 结构校验、引用完整性校验、时间与来源校验、金融语义校验、能力校验及页面边界校验后，在同一事务中保存分析版本、计划、模块编排和对应发布事件。前端只消费完整版本，不把流式半截 JSON 当作正式结论。

模型格式错误可进行一次受限修复；仍失败则保留上个有效版本并标注运行失败。不得把旧结论换上新时间。多个任务通过 `base_revision` 与乐观锁防止后完成的旧任务覆盖较新证据。SSE 事件带单调序号和发布ID，断线可补读，重复事件可去重。

### 记忆分层

| 记忆 | 内容 | 失效与保留原则 |
| --- | --- | --- |
| 当前工作状态 | 活跃周期、观察池、未决约束、条件状态 | 新发布替换当前指针，历史不变 |
| 周期记忆 | 角色变化、分支、事件、阶段修订 | 跨交易日保留，关闭后归档 |
| 证据记忆 | 原文引用、来源、时间、核验结果 | 引用中的证据不随14天行情清理丢失 |
| 案例记忆 | 原假设、反证、最终观察和失效模式 | 仅使用已到评估终点的案例 |
| 用户偏好 | 关注对象、展示固定项、通知偏好 | 用户可编辑，不变成市场事实 |

建议发布与结果元数据默认保留至少一年；引用证据按来源许可保存必要摘录、hash与定位，原始高频行情按数据许可和存储预算另设周期。用户删除工作区时按权限处理相关记录。历史需要修正时增加 correction 事件，保留原值与修正值。

## 10. 数据接入与降级

| 数据 | 所需内容 | 缺失时行为 |
| --- | --- | --- |
| 全市场快照 | 股票范围、价格、成交、涨跌停、源时间 | 降低广度可用性，不能用部分样本宣称全市场状态 |
| 盘中行情 | 正确单位、连续源时间、停牌与交易状态 | 暂停依赖它的条件，不用前收填充 |
| 竞价 | 虚拟价格、匹配/未匹配量、最终成交、采样时间 | 明确显示尚未接通；开盘后规则可继续 |
| 涨跌停与梯队 | 前一日冻结样本、连板口径、ST/新股范围 | 显示未分级和冲突，晋级分母不偷换 |
| 题材 | 业务属性、事件驱动与名称联想分开 | 保留未知，不把供应商概念标签当因果证据 |
| 公告监管 | 发布与适用时间、对象、动作、原文、来源级别 | 不自动解除监控；公司风险提示与交易所监控分开 |
| 异动窗口 | 官方规则、版本、基准、历史价格与重置条件 | 无完整输入时返回不可计算，不生成精确倒计时 |
| 历史研究 | 当时版本与可见证据 | 不能用今天修订后的数据模拟当时知情 |

供应商冲突在同一口径下对比，选择主源与备用源均留痕。首期不承诺交易所级低延迟行情。数据许可、频率、全市场吞吐和竞价能力先做实测，能力清单决定可激活规则。

## 12. 验收和评估

第一版的成功指标是证据与记忆完整、条件状态正确、更新及时、误导性输出减少。收益或胜率不作为没有回测口径的宣传指标。

必须覆盖以下验收案例：

1. 新华跌停且有监管线索时，解释中保留约束；原文缺失时不标已核验。
2. 九阳窗口未知时，页面不能显示确定解禁日期或将周一强势预写为事实。
3. 九阳上涨、其他分支继续弱时，区分核心独强与周期修复。
4. 文投带队、原周期弱时，允许传媒独立情景。
5. 闽发5.44元昨收，按适用规则计算正常涨停约5.98元；不能设置当日收复6.04元为可达触发。
6. 竞价源缺失时为 unknown；不拿零、昨收、虚拟挂单替代真实成交。
7. 停牌、ST、新股无涨跌幅阶段、除权与不同板块规则进入计算前置校验。
8. 行情中断或过期时停止新判断，保持原时间；恢复后重新检查持续条件。
9. 跨日恢复后继续同一个周期和未决问题，未丢失用户补充。
10. 盘中修改阈值产生新版本，原预案复盘仍使用原值。
11. 未来消息不能进入过去快照；次日结果到时才结算。
12. 非法模块、恶意链接、引用缺失、跨用户证据、乱序发布被阻止。
13. SSE断线恢复、任务重复触发、模型超时和预算耗尽可恢复且不重复通知。
14. 桌面、390px移动端、键盘与减少动画模式均可操作。

评估数据应采用走步回放，按交易日冻结输入；记录覆盖率、未知率、条件触发误差、重复/遗漏提醒、修订理由的证据支持率。概率模型如后续引入，需要独立样本校准。模拟交易必须明确T+1、费用、滑点、涨跌停无法成交及资金约束，不能用观察条件命中率替代策略收益。

## 13. 分期交付

| 阶段 | 可交付内容 | 完成门槛 |
| --- | --- | --- |
| P0 数据与契约 | 数据能力清单、事件原文核验、异动计算方案、领域DTO与测试样例 | 不再存在隐式缺失字段；规则与模型职责清楚 |
| P1 盘后与盘前闭环 | 真实Agent生成结构化周期、证据、预案，持久化与七视图渲染 | 同一输入可回放；JSON失败不覆盖有效结果；用户补充跨日保留 |
| P2 盘中持续验证 | 条件执行、节点调度、事件触发、SSE、降级与通知去重 | 实盘时段数据压测通过；未知不误判；重启后可恢复 |
| P3 跨周期复盘 | 结果账本、案例记忆、周期拆分与长期评估 | 无前视回放；冻结分母；历史结果可追溯 |

推荐先完成P1的真实闭环，再增加P2实时能力。竞价能力若未达标，P2先启用连续竞价后的监测，竞价模块明确保持不可用。

## 14. 原型使用与边界

打开 `index.html`，或在此目录运行 `python3 -m http.server 8767 --bind 127.0.0.1`。原型不需要依赖安装、不访问真实账户、不创建真实任务。

- 顶部「演示情景」切换四种结构化快照，观察页面模块与状态变化。
- 左侧七个入口切换主页面和子页面；个股页支持七只股票。
- 点击约束、条件和地图节点可下钻；支持键盘与Esc关闭弹窗。
- 「补充上下文」只在浏览器本地保存待核验线索，不自动修改市场结论。
- 「快照v3」可查看并导出驱动当前页面的JSON。
- 「启用演示监测」与「重放示例分析」均为显式模拟，不调用真实Agent。
- `screenshots/` 保存桌面主视图、子视图、移动端与降级情景；`gallery.html` 集中浏览。

原型示例使用本轮讨论中的名称和收盘数值；盘中快照全部为人为构造的演示情景。不能将其当作周一预测、行情验证结果或已上线能力。关键监管线索继续保留待核验状态。

### 原型验证

复现脚本为 `verify-prototype.py`，需已安装 Google Chrome、Python `playwright` 与 `jsonschema`；这些依赖仅用于原型检查，直接浏览原型无需安装。在本目录启动静态服务器后运行：

```bash
python3 verify-prototype.py --url http://127.0.0.1:8767/
```

脚本检查四种快照的 Schema、引用与时间语义、七个视图渲染、390px与320px布局、键盘操作、弹窗、用户补充转义、JSON导出、主题及网络请求。运行会刷新 `screenshots/` 中的设计预览，并生成本地 `verification.json`；执行结果不纳入源码提交。检查范围限于设计产物，不代表真实 Agent、行情、条件执行器、交易策略或生产服务已通过验证。
